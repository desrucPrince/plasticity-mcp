# Changelog

## Unreleased

- Speed tier 1 polish (review follow-ups): `plasticity_describe_body` is now never longer than 4,096 bytes for any body (every list capped with `more` counts, `name` cut to 120 characters, cylinder groups trimmed by keeping the most faces, whole sections left out as `<section>More` in a fixed order as a last resort; 3,000 cylinder groups in a few ms). A cylinder face with one circle edge reads `kind: "arc"` with `sweepDeg`, in its own group, never `hole` or `boss`. `count` is the number of distinct axes; `faces` appears only when it differs (assertion edits: `speed-tier-1c.test.ts` `count: 3` to `count: 2, faces: 3`, and the golden string in `speed-tier-1d.test.ts` `"count":3` to `"count":2,"faces":3`, both the old face-count meaning). Grouping treats axis components under 1e-6 as 0, merges axis points within 0.001 mm and radii within 0.0001 mm of a group's first radius. A `plasticity_describe_body` batch step without `return` is exempt from the 1,500 byte read rule. `roundMm` rounds only real lengths (not `...PerMm`/`...PerMm2` rates, not the matrix rotation in `matrixWorldMm`) and follows the nearest `Mm`/`Mm2` ancestor in return paths (`matches[*].boundsMm.min`, `matches[*].centerMm[0]`). The batch reply carries `returnErrors: <n>` when any step has `returnError`. Server instructions name the right `sortBy` keys (faces `area|x|y|z`, edges `length|x|y|z`); `find_faces`/`find_edges` descriptions state the 8 KB cut and that only `limit` lifts it. The stale-revision errors of exact solid properties and interference now read like the others ("Stale reference: expected revision X, current revision is Y"). Live check: `discovery/speed-2026-11/describe-check-{a1,b,c}-polish.json`, `describe-check-a1-lean-batch-polish.json`.
- `plasticity_set_driving_distance` round 3: the native helper records when the drive step calls the dialog's `finish()`. A timeout after `finish()` is now undetermined (session uncertain, `plasticity_reconcile`) unless the commit is seen to land in a 250 ms settle window (then it is read back as a normal commit); only a cancel before `finish()` reports "the document is unchanged". Live on 26.1.3 a cancel 0-10 ms after `finish()` discarded the commit in every trial (`discovery/probes-2026-11-followups/probe-late-commit.json`), one build only. A commit with no Undo step that misses the requested distance fails with "Plasticity made no change". The read-back now requires the moving face's own plane to change (offset counts before and after, "make flush" allowed) and accepts either side of the reference; a face already at the target or a different face moving there is an error. Slot walls, a reversed stepped pair and non-parallel single-face rejection verified live and added to `accept:native-driving-distance`. Foreign commands are named in failures, early interruptions read as interrupted, and a build without `Face.GetAnyPointOn` fails before starting. Test edits: three assertions on the after-finish hang path (it is uncertain now).
- Face control points: faces split on one B-Surface (identical grids) are refused before the show edit; hide works by face even when the shown points cannot be attributed; `undoSteps` is measured from the Undo depth for show, hide and move; the move read-back tolerance is max(1e-3 mm, |coordinate| x 8e-7) per axis and is reported on failure; show returns `grids: [{ faceId, u, v }]` and `renumbered`. Moving one of two coincident shared-edge points alone is verified live (the twin stays, Plasticity reshapes the face, the body stays valid) and the read-back error names the separation. Live cases added to `accept:native-patch-polysplines-facepoints`. Test edit: the twin-grid show assertion now expects the pre-edit refusal.
- Probe hygiene: `discovery/probes-2026-11-followups/env.sh` and `discovery/probes-2026-11-pick/env.sh` require Node 24 on PATH instead of a home-directory path; the follow-ups harness reads `PLASTICITY_CDP_URL` and `PLASTICITY_TARGET_ID` and refuses any host but 127.0.0.1.

- Speed tier 1d (faults found in real-model transcripts): `plasticity_create_rib` states its direction (positive thickness runs along the profile's right-hand normal; verified live), takes `side` (`centered`, `positive`, `negative`) and `keepProfile`, and returns `ribBoundsMm`; `plasticity_fillet` and `plasticity_chamfer` take `edgeQuery` (a find_edges query, with `sortBy`/`order`/`limit`, plus an `adjacentFace` shorthand for "the edges of this face") instead of `edgeIds` and reply with `edgeCount`, `plasticity_extrude_faces` takes `faceQuery`; `plasticity_describe_body` takes `ids` (1-8) or no id (all bodies when 8 or fewer), adds `through`/`extentMm` per cylinder group and an open-top `cavity` when the planes say so; cut find replies start with a concrete `next` move; a lean batch `plasticity_status` step without `return` replies with a header; `keepProfile: false` on the rib and the countersink recipes deletes their construction Wires. Existing calls reply as before. One test assertion edit: `plasticity_describe_body` with no arguments is valid now.
- Batch state reuse review fixes: inside `plasticity_batch` every cached state answer is now probed in the same call (was: only the first read of a step), so a UI edit during a download, native read or solver run inside a step fails that tool's "document changed while ..." guard as it does in a direct call; a state read is cached only when no mutation started while it was pending. A bad `return` path on a step that changed the document no longer fails the applied step: it stays completed with `returnError` and the batch goes on (read steps still fail, now naming the result's top-level keys). Return paths read only own result keys (`__proto__`, `constructor`, `prototype`, inherited keys are refused). Lean `{ status }` and `{ count }` replies add `omitted: [keys]`. `roundMm` rounds only length values (keys ending in `Mm`/`Mm2`), also in the `verbose` top level. In a batch, `sortBy: "area"` uses the probed state; its stale-revision error now reads like the other stale-reference errors. Benchmark: `discovery/speed-2026-11/parts.ts --tier1b a1 --suffix=fix1`.
- Speed tier 1c: new read-only `plasticity_describe_body` (compact tool list): a 1-2 KB description of one body (bounds and size, planar faces by outward normal with plane positions and largest face ids, cylinders by radius and axis with hole/boss and axis points, other surfaces, blend radii) from the read model, no native call; `plasticity_body_info` stays for exact topology and takes `faces`/`edges`/`vertices` booleans plus a `hint` on replies over 20,000 bytes; direct `plasticity_find_faces`/`plasticity_find_edges` calls without `limit` are cut to 8,000 bytes with `count`, `truncated` and `hint` (batch steps and explicit `limit` are never cut); the server instructions point agents to them. Live check: `discovery/speed-2026-11/parts.ts --tier1b --describe a1 b c`.
- Speed tier 1b: inside `plasticity_batch` an edit step does one full state read instead of 5-7 (a native revision probe guards each reuse; a UI edit between steps still fails as a stale revision; direct calls, journal entries and replies unchanged; journal fsync stays per step). In `detail: "lean"`, recipe steps reply `{ status }` without their step journal and a read that a later step references replies `{ count }` (plus `ids` up to 8). `plasticity_find_faces` takes `sortBy: "area"` (exact native area, `areaMm2` on each match, at most 256 matches). Benchmark: `discovery/speed-2026-11/parts.ts --tier1b`.
- Speed tier 1 for agents: `plasticity_batch` steps take `return: [paths]` (no silent cut of read results over 1,500 bytes; a `truncated` note with a hint instead), batch takes `detail: "lean"` (no `createdEdges` echo, no consumed bodies, no empty lists, one `summary`; default stays `standard`) and `roundMm`, and step replies carry tool-specific fields (export `path`/`bytes`, `controlPoints`, `previousDistanceMm`). `plasticity_find_faces`/`plasticity_find_edges` take `sortBy`, `order`, `limit` (`count` stays the total). The compact tool list adds the rib, screw boss, connector opening, through-hole and countersink pattern recipes, interference and parallel-face clearance checks, and `plasticity_set_driving_distance`. Descriptions say that cylinder `centerMm` is the base centre and that `boundsMm` matches by overlap. Benchmark: `discovery/speed-2026-11/parts.ts --tier1`.
- Add `plasticity_sweep_curves` (Wire profiles to Sheets), `guideIds`/`guideMethod` rails on `plasticity_sweep_regions`, `shape`/`targetId`/`merge` on `plasticity_extend_sheet_edges`, and `plasticity_move_measurement_label`. Live script: `accept:native-extend-sweep-label` (label move checked on X, Y and Z measurements; multi-profile sweep gives one Sheet per profile).
- Add `plasticity_xsided_patch` (N-sided Sheet from boundary Wires or edges, optional guides and g0/g1/g2 edge continuity), `plasticity_convert_reference_mesh_to_polysplines` (quad reference mesh to a PolySplines solid; the mesh is consumed) and `plasticity_show_face_control_points` / `plasticity_move_face_control_points` (Sheet and Solid face CVs). Live script: `accept:native-patch-polysplines-facepoints`.
- Live acceptance scripts for the three new groups now require `PLASTICITY_CDP_URL`, force `PLASTICITY_AUTO_LAUNCH=0` and `PLASTICITY_HUD=0`, and recover the baseline in `finally`. Native enum lookups (sweep guide method, extension shape and type, continuity) fail with a clear error when the build lacks the member.
- Add `plasticity_set_driving_distance`: set the distance between two parallel planar faces (or one face and the opposite face Plasticity finds) by moving the chosen face, like Plasticity's Dimension tool, in one Undo step. It runs the real `DimensionDistanceCommand` through a generic internal pick-command helper that seeds the selection click point, finishes the dialog, cancels in the same call on a stall and always clears the selection and hits. Live script: `accept:native-driving-distance`.
- `plasticity_set_driving_distance` review follow-ups: once the command starts, the native helper never throws (a cancel that throws is "cancel failed"), it cancels only its own command, it reads the command error inside `execute()` because the executor swallows it, and it marks the session uncertain for any undetermined end. An equal distance is a no-op (`changed: false`, `undoSteps: 0`). Each commit is read back and returns `movedFaceId` and `planeOffsetMm`. The click point is the kernel's own point on the face, so washer-like faces work in single-face mode. Same-direction (stepped) pairs are allowed. The 26.2 store route binds `DimensionDistanceSpaceDialog`. Verified on 26.1.3 only.
- Face control points on multi-face bodies: each point carries `faceId` and grid `index`, attributed by matching the face's kernel control grid; show returns only the requested faces. `cvId` is now a string, Plasticity's control point `versionId` (was an integer index): Plasticity renumbers its indexes when another face is shown or hidden, and the `versionId` changes with every edit, so a stale `cvId` is rejected instead of moving another point. Add `plasticity_hide_face_control_points`. Non-BSurf faces are refused before any edit, and a second show or a hide of an unshown face costs no step. Moves are read back against the delta. X-sided patch and PolySplines descriptions now state only what was verified live (Solid edge loops, guides with edges, triangle meshes, `interpolateBoundary` and `mergePatches` on an open grid).
- Polish IGES/SAT export: always stage `geometry.igs`, report a missing file clearly, fix the validator wording. `plasticity_clear_selection` is strict, non-destructive and findable as deselect, unselect or select none.
